Chapter 01

Know what you are presenting

A learning guide tied to this repository, from first principles to an oral defense.

This project classifies a 28 × 28 grayscale clothing image into one of ten Fashion-MNIST classes. The LSTM reads the image as a sequence of rows. The Transformer reads it as a sequence of small patches. Both end with ten class scores and use the same supervised training pipeline.

LSTM

Read, remember, classify

28 steps × 28 pixels → a 128-feature final hidden state → 10 scores.

82,186 trainable parameters · 88.48% test accuracy

Transformer

Compare patches, combine, classify

49 patches × 16 pixels → 64-feature tokens → 2 encoder blocks → mean pooling → 10 scores.

71,946 trainable parameters · 85.55% test accuracy

Chapter 03

The minimum mathematics, explained

Tensors, learned features, activations, and gradients are the vocabulary of both models.

A tensor is an array with named roles for its axes

A scalar has one value. A vector is a list of values. A matrix has rows and columns. A tensor generalizes these to more axes. The tuple (B, 49, 16) means B independent images, 49 patches per image, and 16 scalar pixel features per patch. An axis length does not tell you its meaning: always name the axes.

B is batch size, T sequence length, D feature width, H LSTM hidden width, C class count. One batch is a group of independent examples processed together. It is not one long sequence formed by concatenating images.

A linear layer learns weighted combinations

y = Wx + b   (column-vector notation)
For row-vector batches: Y = XWT + b

nn.Linear(in_features, out_features) stores a weight of shape (out_features, in_features) and a bias of shape (out_features,). It transforms the last axis and keeps earlier axes. Thus Linear(16,64) maps (B,49,16) directly to (B,49,64) using the same weights for every patch.

A parameter is a learned number, such as a weight or bias. A hyperparameter is a chosen setting, such as learning rate or hidden size. An activation is an intermediate value produced for a particular input. The hidden state is an activation, not a persistent trainable table for individual images.

What learning actually does

A forward pass computes scores and a loss. Backpropagation uses the chain rule to compute how each parameter affects that loss. The optimizer uses those derivatives to update parameters. Repeating this over many batches can improve predictions on unseen images. Generalization must be measured on held-out data; a low training loss alone cannot establish it.

For a composition L = f(g(w)), the derivative is dL/dw = f′(g(w))g′(w). Deep networks combine many such factors. Very small products can make learning early computations difficult; very large products can make it unstable. This motivates gated memory, residual paths, and normalization.

Logits are not probabilities

A logit is an unconstrained real-valued class score. The output shape is (B,10), not ten predicted labels per image. argmax(dim=1) chooses one class per image. Applying softmax preserves the winning class because it preserves score ordering.

The exact preprocessing order

  1. ToTensor() converts byte pixels into float32 values in [0,1] and creates shape (1,28,28).
  2. The training-only mean and standard deviation are computed across all pixels of the 54,000 training images. The code accumulates totals in float64; statistics are population-style, using E[x²] − E[x]².
  3. Every split uses these same training statistics. No per-image normalization is performed.
  4. The normalized image is converted to its model representation. DataLoader then stacks examples along a new batch axis.
Z[0,r,c] = (I[r,c] / 255 − μtrain) / σtrain
μ = 0.28620901297676965   σ = 0.3531597492723218

A black pixel becomes about −0.8104. A white pixel becomes about 2.0212. Negative inputs are expected after normalization. This global transform does not force every individual image to have mean zero and standard deviation one.

Why use the training split only?

Preprocessing is part of what the model learns from data. Computing statistics from validation or test images would let held-out distribution information influence training. Labels need not be exposed for leakage to occur. The test set should remain a final assessment, not a tool for choosing architecture or checkpoint.

The split cache stores the indices, seed, ratio, dataset hash, split hash, mean, and standard deviation. The code recomputes expected indices and checks cache compatibility before reusing it. A hash detects a mismatch; it does not prove the dataset or experiment is scientifically correct.

No augmentation in these runs: both configs set augment_train=false. The data wrapper can perform a horizontal flip and small rotation when enabled, but those transforms were not used for the saved LSTM or Transformer.

Chapter 05
LSTM: read an image as 28 rows
The sequence is spatial. It is not a video, sentence, or stream of 784 time steps.


LSTM means Long Short-Term Memory. It is a recurrent neural network designed to maintain and update information along a sequence. In this project, step t is image row t, read from top to bottom. Each step receives 28 pixel features, ordered left to right.


S[r,c] = Z[0,r,c]
(1,28,28) → squeeze channel → (28 steps,28 features)
After batching: X ∈ ℝB×28×28


No pixel is discarded: 28 × 28 = 784 scalar values. The layout change does not itself learn anything. At each step, learned input weights combine all 28 horizontal pixel positions; recurrence lets the model combine that row with previous rows.


row 0
28 pixels→LSTM state→row 1 … row 27→final h
128 values→dropout → Linear → 10


The architectural choices actually used
  • One recurrent layer, one direction, input width 28, hidden width 128.
  • Zero initial hidden and cell states for every image on every forward call.
  • No recurrent state carried between images or mini-batches.
  • Final hidden state only; no averaging of all row outputs and no attention readout.
  • Dropout probability 0.2 on the final hidden vector, followed by Linear(128,10).


A single recurrent layer is reused at all 28 steps. There are not 28 separately parameterized LSTMs. Increasing the sequence length changes computation and activation storage, but does not automatically increase this layer's parameter count.


What the final state means
The final state is computed when the last row is read, but depends recursively on all preceding rows. Saying “the model uses only the bottom row” confuses the final input with the accumulated state.


Why an LSTM for an image?
It provides a way to test sequential feature aggregation on a vision task and to compare it with dense and convolutional models. It imposes a top-to-bottom processing order. That order is a modeling choice, not a natural time axis of clothing. Rotating or reversing an image changes what arrives early and late.


Chapter 06
Inside the LSTM cell
One cell has a memory state, an exposed state, three gates, and a candidate update.


At step t, let xt be the current row (28 values), ht−1 the previous hidden state (128 values), and ct−1 the previous cell state (128 values). Each gate below is a 128-dimensional vector. The equations use column-vector notation.


it = σ(Wiixt + bii + Whiht−1 + bhi)
ft = σ(Wifxt + bif + Whfht−1 + bhf)
gt = tanh(Wigxt + big + Whght−1 + bhg)
ot = σ(Wioxt + bio + Whoht−1 + bho)

ct = ft ⊙ ct−1 + it ⊙ gt
ht = ot ⊙ tanh(ct)


SymbolPlain meaningExample intuition
f: forget gateScale the previous cell memory coordinate by a number between 0 and 1.Keep much of a useful accumulated feature, or allow it to fade.
i: input gateChoose how much of the candidate to write.Write a newly detected row pattern strongly or weakly.
g: candidatePropose signed content to add to memory.A learned feature can increase or decrease a memory coordinate.
o: output gateControl how much transformed memory is exposed as hidden state.The cell can retain information while exposing only some of it.
c: cell stateThe recurrent memory path, updated additively.Carries accumulated features; can exceed the interval [−1,1].
h: hidden stateThe output sent to the next step and, at the end, the classifier.Bounded by tanh and the output gate before the final dropout.


The gates are learned functions of the current row and previous hidden state. They are not handwritten rules such as “forget background.” Human descriptions of memory coordinates are intuition, not evidence that individual learned dimensions have a specific semantic meaning. This implementation has no peephole connections from c directly into the gates.


One numerical coordinate
Suppose ct−1 = 0.8, f = 0.9, i = 0.2, g = −0.5, and o = 0.7. Then ct = 0.9 × 0.8 + 0.2 × (−0.5) = 0.62. The new hidden value is 0.7 × tanh(0.62) ≈ 0.386. One part retained old information; another part wrote a negative update.


Memory gate laboratory
A single coordinate with manually chosen gate outputs, not the trained network. In the real model, affine layers plus sigmoid/tanh compute these values.


Try f=1 and i=0 to preserve c exactly; then set o=0. The exposed h becomes zero while the cell still stores its memory. Values 0 and 1 are idealized limiting cases for sigmoid gates.


How PyTorch packs the four computations
weight_ih_l0 has shape (512,28); weight_hh_l0 has shape (512,128). The two bias vectors each have 512 values. The packed gate order is i, f, g, o. One pair of matrix multiplications computes four preactivations together; splitting the 512 features recovers four 128-feature vectors.


The current code leaves initialization to nn.LSTM; it does not explicitly set the forget-gate bias to 1. Be careful: many tutorials recommend a custom forget bias, but that is not a change present here. Parameter storage and default state behavior can be checked in the PyTorch 2.9 LSTM API.


Chapter 07
Why memory helps, and how it learns
Backpropagation through time connects the final classification loss to earlier rows.


Start with a plain recurrent network
ht = tanh(Wxxt + Whht−1 + b)


Backpropagating through many such transitions multiplies recurrent matrices and activation derivatives. Tanh derivatives are at most one and often much smaller. Depending on weights and states, gradients may shrink or grow across steps. This makes learning long dependencies difficult.


The LSTM adds a controlled additive path
Along the direct cell-memory path, holding gate values fixed, ∂ct/∂ct−1 = diag(ft). If forget values remain close to one, this route can carry information and derivatives with less repeated contraction. Across many steps, its coordinate-wise factor is a product of forget values.


Direct memory-path factor across 28 transitions:
0.528 ≈ 3.73 × 10−9
0.9928 ≈ 0.755


This is a partial-path explanation, not the complete total derivative: gates also depend on earlier hidden states. LSTMs mitigate vanishing gradients; they do not guarantee perfect memory or eliminate exploding gradients. Gate saturation, output tanh saturation, optimization, and the task all matter.


Backpropagation through time (BPTT)
  1. Conceptually unroll the same cell across 28 row steps.
  2. Compute the final hidden state and classification loss.
  3. Apply the chain rule backward through each state transition.
  4. Sum the contributions to shared weights from all steps.
  5. Let Adam update the weights once for the mini-batch.


The model's forward pass is sequential along rows. The framework still vectorizes work across B images and hidden features. No state is detached partway through the 28 steps, so this is full BPTT for each image, not truncated BPTT over subsequences. The code does not call gradient clipping.


Why final hidden state instead of the cell?
The hidden state is the LSTM's exposed representation: an output-gated tanh transformation of cell memory. The classifier is trained to use that representation. Using the final cell, averaging all hidden outputs, using a bidirectional LSTM, or adding attention would be different architectures requiring a new experiment.


What this design gives up
Earlier rows must influence the classifier through later recurrent transitions. The 128-dimensional final vector is a fixed-size summary of the whole image. A convolutional model has stronger explicit local two-dimensional structure; this LSTM instead learns row features and their ordered relationships. These observations motivate comparisons, but they do not establish the cause of a particular accuracy gap.

Why dropout is outside the LSTM
PyTorch's built-in LSTM dropout applies between stacked recurrent layers. This model has one layer, so its useful explicit dropout is on the final readout. With p=0.2, training drops each readout element with probability 0.2 and scales retained elements by 1/0.8. In evaluation it is an identity operation. The gate recurrence itself has no configured dropout.


Chapter 09
Transformer: the image becomes 49 tokens
This is a small encoder for image classification, trained from scratch.


A Transformer uses attention to combine information across a sequence. Here, each token begins as a non-overlapping 4 × 4 image patch. A 28 × 28 image has a 7 × 7 grid of such patches: 49 tokens, each containing 16 normalized pixel values. The word “token” does not imply text.


P[7r+c, 4i+j] = Z[0, 4r+i, 4c+j]
r,c ∈ {0,…,6}; i,j ∈ {0,…,3}
(1,28,28) → (49,16) → batch → (B,49,16)


Patches are visited left-to-right across the first patch row, then across the next patch row. Pixels inside each patch are flattened left-to-right, top-to-bottom. Patch 0 covers image rows 0–3 and columns 0–3; patch 1 covers rows 0–3 and columns 4–7; patch 7 begins rows 4–7 and columns 0–3.


Patchification preserves all 784 pixels. It rearranges them. It is not mean pooling, random sampling, or a learned compression. The next learned linear layer produces features.


Why unfold followed by contiguous and view?
Python
patches = image.unfold(1, 4, 4).unfold(2, 4, 4)
# shape: (1, 7, 7, 4, 4)
patches = patches.contiguous().view(-1, 16)
# shape: (49, 16)


unfold(dimension,size,step) exposes windows along the selected axis. Using step=size makes them non-overlapping. The resulting tensor is a strided view; contiguous() puts the values into a suitable ordered memory layout. view(-1,16) merges the patch-grid axes and flattens each local patch. Here -1 asks PyTorch to infer 49. It does not mean “last patch.”


The complete architecture at a glance
49 × 16
pixel patches→Linear 16→64
+ positions→2 pre-norm
encoder blocks→LayerNorm

Each block uses four attention heads and a 64→128→64 feed-forward network with GELU and dropout 0.2. There is no decoder, no text tokenizer, no causal generation, no pretrained weights, no class token, and no convolutional patch stem.


This is a compact Vision Transformer-style classifier. The original Vision Transformer paper motivates patch sequences, but its training scale and standard configurations should not be attributed to this small experiment.


Chapter 10
Patch embeddings and positional information
An image patch supplies content; a learned position vector supplies its location.


Patch projection
ep = WembedPp + bembed ∈ ℝ64
zp(0) = Dropout(ep + Epos[p])


Linear(16,64) transforms each 16-pixel patch into a 64-feature token. Those features are learned combinations of local pixels. Expanding 16 to 64 provides a representation space; it does not create new measured image information. The same projection is shared across all patch positions.


Learned absolute position embeddings
position_embedding is a trainable tensor of shape (1,49,64). Its leading size-one axis broadcasts across B images, so each image receives the same trainable position table. Position p gets a distinct 64-vector that is added to its content embedding.


nn.Parameter registers this tensor for optimization. It starts with a truncated normal initialization using std=0.02; then classification gradients update it. It is neither a sinusoidal formula nor an embedding of the class label. The 49 entries are absolute raster-grid positions learned for this fixed input resolution. There is no explicit relative-position bias or separate learned row/column table.


Why attention alone cannot identify arrangement
With no position information, self-attention is permutation equivariant: permuting the input tokens permutes the output tokens in the same way. A token-wise feed-forward network and LayerNorm preserve that property. Mean pooling then removes order, making the whole classifier permutation invariant in evaluation.


Concretely, a bag of identical patch contents arranged differently would give the same pooled result if the position embeddings were zero. With the position table active, moving patch content to a different fixed slot changes which position vector is added and can change the prediction.


A precise permutation statement
Permuting content tokens while keeping the position table fixed generally changes this model. Permuting the already position-tagged token vectors as a group would still leave mean pooling invariant. Position matters through content–location pairing, not because token index has a hidden special meaning inside attention.


What the tests establish
The Transformer tests reverse patch order and check that outputs change. They then zero the positional table and check approximate permutation invariance in evaluation. These checks establish useful architectural behavior; they do not measure the accuracy loss from training an entirely new model without positions.


Chapter 11
Self-attention, from one score to four heads
Every patch can collect information from every other patch in the same image.


Queries, keys, and values
For one head, learned projections make three versions of each token: a query expresses what the receiving token matches; a key is used to score each source token; a value is the information that will be mixed. These are mathematical roles, not natural-language questions. In self-attention, Q, K, and V come from the same input token sequence, with different learned projections.


Q = XWQ + bQ,   K = XWK + bK,   V = XWV + bV
S = QKT / √dk
Aij = exp(Sij) / Σm=149 exp(Sim)
Y = AV


This uses row-token notation. In each attention row i, the softmax runs over source-key index j. Aij says how much value j contributes to the updated token i, before attention dropout. It is not a probability that patch j belongs to a class. All 49 keys, including i itself, are eligible.


Without dropout, each attention row sums to one and Yi is a weighted average of the projected values. The score matrix need not be symmetric: Q and K have different learned projections, and row normalization is directional. Large attention weights alone are not a complete explanation of a model's decision.


Why divide by the square root?
If query/key components have roughly unit variance and are sufficiently independent, a sum of dk products has variance that grows with dk. Dividing by √dk moderates score scale and helps avoid excessively saturated softmax. Here dk=64/4=16, so the divisor is 4. It is not √64 and not √49.


A hand-computable example
Use one two-dimensional query q=(1,0), keys k₁=(1,0), k₂=(0,1), k₃=(1,1), and values v₁=(2,0), v₂=(0,2), v₃=(1,1). Raw dot products are (1,0,1). After division by √2, scores are about (0.707,0,0.707). Softmax gives (0.4011,0.1978,0.4011). The output is about (1.2033,0.7967).


Attention laboratory
Toy 3-token, 2-feature calculation. These vectors are illustrative and are not learned patch features from the checkpoint.
Try q=(0,0): all three scores tie, so weights are 1/3. Try a large positive query and toggle scaling to see the distribution become more or less concentrated. The browser uses max-subtraction for numerically stable softmax.


Four heads, then one output projection
The 64-dimensional projections are split into four 16-dimensional heads. Each head computes its own 49×49 attention pattern. Concatenating the four outputs restores width 64, then a learned output projection mixes these channels. The heads are not four encoder layers or four separate classifiers.

The combined PyTorch input projection stores in_proj_weight of shape (192,64) and bias (192,). The output projection has weight (64,64) and bias (64,). The code does not impose human-assigned specializations on heads. Two heads can learn similar behavior.


Why there is no mask
All 49 real patches are present; no sequence padding is needed. An image classifier is allowed to inspect the whole image, so later raster positions are not forbidden. A causal mask is useful in next-token generation but would impose an unnecessary restriction here. Attention mixes tokens within each image, not across unrelated batch examples.


For the reference formulation see Attention Is All You Need; implementation-specific shapes and head splitting are documented in PyTorch MultiheadAttention.


Chapter 12
What an encoder block actually computes
Attention mixes positions; the feed-forward network transforms features at each position.


Pre-normalization and residual connections
Let X be the input to one block. This implementation sets norm_first=True, so it normalizes the input to each sublayer before applying that sublayer. A simplified expression, with the correct operation order, is:


U = X + Dropout₁(MHA(LN₁(X), LN₁(X), LN₁(X)))
Y = U + Dropout₂(Linear₂(Dropout(GELU(Linear₁(LN₂(U))))))


The repeated LN₁ symbols indicate the same normalized input used as query, key, and value; this is not three independently learned norms. MHA also includes dropout on attention weights during training. Residual additions retain a direct X→U and U→Y path while the sublayers learn modifications. Their shapes must match, which is why both sublayers return width 64.


Layer normalization
LN(x)j = γj(xj − μx) / √(σ²x + ε) + βj


For each token independently, mean and variance are computed across its 64 features. Learned γ and β each have 64 entries. The default ε is 10⁻⁵ and variance uses the population form. It does not compute statistics across images or normalize the attention probabilities. Unlike BatchNorm, it has no running batch statistics. It behaves the same way in train and eval modes apart from the values arriving from dropout upstream.


The feed-forward network (FFN)
Each token is transformed by Linear(64,128) → GELU → Dropout → Linear(128,64), with shared weights across all 49 token positions. It temporarily expands features then maps back to width 64. It does not map the 49 token axis to 128 tokens; the sequence length stays 49.


Attention supplies communication among patches. The FFN supplies nonlinear processing of the resulting features at each patch. Combining them lets a block do more than merely average neighboring information.


Two independent blocks
The list comprehension constructs a new TransformerEncoderLayer twice. The blocks have the same architecture but distinct trainable tensors and independently drawn initial weights. Reusing the same object twice would share weights and define a different model. ModuleList registers both blocks for optimization; the explicit for loop determines execution order.


Final norm and mean pooling
After both blocks, tokens return to shape (B,49,64). The model applies a final LayerNorm(64) to each token, then mean(dim=1) averages the 49 tokens into a single 64-feature image vector. Dropout and Linear(64,10) produce the class scores.


gb,d = (1/49) Σp=048 LN(Tb,p,:)d
logits = Linear64→10(Dropout(g))


Mean pooling uses all contextualized output tokens. It is not averaging raw pixel patches, averaging probabilities, or selecting a special class token. Norm-before-mean is the actual order: LayerNorm and mean pooling generally do not commute.


Relevant APIs: TransformerEncoderLayer and LayerNorm. The local code determines which options are enabled.

Why sequence-first here?
The source comment records that fused batch-first inference on the project's CUDA stack drifted from the float32 CPU result. The blocks therefore use batch_first=False and explicit transposes. This is a backend-compatibility choice recorded by the implementation, not a mathematical requirement of Transformers. It does not mean the LSTM must also be sequence-first.


A Transformer can be implemented batch-first. Changing only the flag without adjusting the input would make it interpret the image batch as the sequence axis, mixing examples and breaking the model. The existing tests compare batched and individual inference and check CPU/CUDA agreement. This guide rechecked the current checkpoint on a CPU/device batch; it did not reproduce the historical fused-path issue.

Complexity without misleading speed claims
For N tokens and width D, dense attention has a score/value-mixing term O(BN²D), plus projection terms O(BND²). The FFN costs O(BNDF), with F=128 here. The explicit attention weight layout has B × heads × N² entries, although fused kernels can avoid materializing some arrays. With N=49 and four heads, that is 9,604 score entries per image per block.


The LSTM costs roughly O(BTH(I+H)) with T=28, I=28, H=128, and four gates as a constant factor; it has a sequential dependency across T steps. Attention can operate on all patch positions within a block in parallel, while the two blocks still run in order. More parallelism does not guarantee faster end-to-end inference for a small model on a particular device.


If patch size changed from 4 to 2, tokens would increase from 49 to 196 and the attention score count would grow by 16×. If patch size were 7, there would be 16 tokens, each with 49 input features. Batch and epoch arithmetic
54,000 = 421 × 128 + 112, so each epoch has 422 optimizer steps, with 112 images in the last batch. Ten epochs give 4,220 updates. Validation has 47 batches; the last has 112 images. Test has 79 batches; the last has 16 images. The loaders do not drop those last batches.


For reported epoch loss, the code multiplies each mean batch loss by the actual batch size, sums, then divides by total images. Averaging the batch means equally would overweight the shorter final batch. Epoch accuracy and macro-F1 are computed from all accumulated labels and predictions.


Train versus validation versus test
Training uses model.train(True), enabled gradients, and Adam. Validation calls the same epoch function without an optimizer, causing model.train(False) and disabled gradient recording. Evaluation reloads the chosen checkpoint, calls eval(), and uses inference_mode(). eval() changes dropout behavior; by itself it does not disable autograd.


Training metrics are collected across batches while the weights are changing and dropout is active. Validation measures the end-of-epoch model with dropout disabled. A higher validation accuracy than training accuracy can therefore occur without data leakage. It still deserves inspection if unexpectedly large.

Oral examination questions
Answer aloud first, then open the explanation. The question filter searches these cards only.
01. Why can an LSTM classify a still image?
It only needs an ordered sequence of feature vectors. Here each image row is one step; the order is spatial rather than temporal.
02. Is the LSTM sequence length 784 or 28?
28. Each step has 28 pixel features. A 784-step pixel-by-pixel LSTM would be a different representation.
03. Are pixels lost when the image becomes rows or patches?
No. Rows retain 28×28=784 values; patches retain 49×16=784 values. The order changes for patches, not the total information in the representation.
04. What is the difference between h and c?
c is the gated additive cell-memory path. h is the exposed state o⊙tanh(c), used for the next transition and the final classifier. Both have width 128 here.
05. What are the four packed gate chunks?
Input i, forget f, candidate g, output o. Sigmoid for i/f/o, tanh for g.
06. Does the forget gate choose individual old rows to erase?
Not explicitly. It scales each coordinate of an accumulated memory vector. Coordinates are learned features, not stored rows.
07. Does the final hidden state see only the final row?
No. It receives the final row and a state that recursively depends on earlier rows. Forgetting may attenuate information, but the dependency spans the sequence.
08. Why hidden[-1] rather than hidden[:, -1]?
hidden has shape (layers×directions,B,H). hidden[-1] selects the last layer/direction and keeps the whole batch. hidden[:, -1] selects the last image along B.
09. Does batch_first=True change h_n to (B,1,128)?
No. It changes only input and all-step output layouts. h_n and c_n remain (1,B,128) in this model.
10. Does the LSTM remember the previous mini-batch?
No. No initial state is supplied, so the forward call initializes zero h/c for each new image. No recurrent state is stored for reuse.
11. Why not set dropout=0.2 inside this one-layer LSTM?
Built-in LSTM dropout is between recurrent layers. There is only one layer. The explicit readout Dropout(0.2) is what regularizes this classifier.
12. Does an LSTM completely solve vanishing gradients?
No. Its additive memory path can help when forget gates retain information, but saturation and other paths still affect learning.
13. How does the loss reach the first row?
Backpropagation follows the recurrent graph from the final classifier through all 28 steps. Shared gate weights receive contributions from each step. Existing tests check nonzero early-row gradients.
14. Why does the LSTM have two bias vectors?
PyTorch stores separate input-hidden and hidden-hidden biases for all four gates. Both are counted, even though their sum appears in the affine preactivation.
15. What is one Transformer token here?
Initially a 4×4 patch flattened to 16 values; after projection and positions, a 64-feature vector associated with that patch location.
16. Why exactly 49 patches?
28/4=7 patches per image axis, so 7×7=49. They are non-overlapping and cover the image.
17. Is patch_embedding a word lookup table?
No. It is a learned Linear(16,64) on continuous pixel features. The position tensor is a separate learnable table.
18. Why add positions before attention?
Attention alone does not know absolute token locations. Adding a distinct trainable vector associates each patch content with its grid slot.
19. Are positions sinusoidal or learned?
Learned absolute positions: nn.Parameter of shape (1,49,64), initialized with a truncated normal std=0.02.
20. What do Q, K, and V mean?
Different learned projections of token features. A query is compared with keys to compute weights; values are combined using those weights.
21. Why is the attention divisor 4?
Each head has width d_k=64/4=16. Scaled dot-product attention divides by √16=4.
22. Does four heads mean four 64-feature attention outputs concatenated to 256?
No. Each head has 16 output features. Four heads concatenate to 64, then an output projection mixes them.
23. Over which axis is attention softmax applied?
Over the 49 key/source tokens separately for each query and each head, within one image. Not over images and not over classes.
24. Must attention be symmetric?
No. Q and K are projected differently, and row-wise normalization is directional. A_ij can differ from A_ji.
25. Do attention weights always sum to one during training?
The softmax probabilities do before dropout. Attention dropout can change the sum of the effective weights for an individual stochastic training pass. In evaluation dropout is disabled.
26. Why is there no causal mask?
The full image is available for classification. Every patch may inspect every other patch. Causal restrictions are needed for different tasks such as predicting future text without seeing it.
27. Can a patch attend to patches in another image in the batch?
Not when the axes are correct. B identifies independent attention examples. The explicit transposes preserve that role; tests compare batched and separate inference.
28. What is pre-norm?
LayerNorm is applied before attention and before the FFN. Each sublayer result is then added residually to its input. norm_first=True enables it here.
29. What is the role of the FFN?
It applies a shared nonlinear 64→128→64 transformation at each token. Attention exchanges information between locations; the FFN transforms features at a location.
30. What does LayerNorm normalize?
The 64 features of each token independently, with learned scale and bias. It does not normalize across the batch or maintain running batch statistics.
31. Are the two encoder blocks sharing weights?
No. The list comprehension instantiates two separate modules with distinct parameter tensors. ModuleList registers them and the loop applies them sequentially.
32. Why transpose before and after the encoder?
The blocks use sequence-first layout (49,B,64), while the surrounding model uses batch-first (B,49,64). Transpose swaps axes without changing token membership.
33. Why does the classifier use mean pooling?
It creates one fixed-size image representation by averaging contextual output tokens. It is a simple readout without a special class token; its superiority to other readouts was not tested here.
34. Does mean pooling make the full model position-blind?
No. Token representations already depend on content–position pairings and attention interactions. Without positions, self-attention plus mean pooling would be permutation invariant in eval mode.
35. Why does the classifier not end in softmax?
CrossEntropyLoss expects raw logits and performs log-softmax internally. Evaluation applies softmax only when it needs reported confidence, while argmax can use logits directly.
36. What changes between model.train() and model.eval()?
Dropout is random and scaled in training, disabled in evaluation. eval() alone does not turn off gradient recording; the code separately uses disabled gradients or inference_mode.
37. What does loss.backward() do?
Computes gradients by reverse-mode automatic differentiation. It does not update weights. Adam performs the parameter update in optimizer.step().
38. Why clear gradients before every mini-batch?
PyTorch accumulates gradients into parameter .grad fields. This training loop intends a fresh update from each batch, so it clears the previous gradients.
39. How many optimizer steps are performed?
ceil(54,000/128)=422 per epoch, or 4,220 in ten epochs. The final training batch has 112 images.
40. Why is the LSTM checkpoint epoch 9 rather than epoch 8?
The selection metric is validation loss, not validation accuracy. Epoch 9 has a lower validation loss even though epoch 8 accuracy is slightly higher.
41. Is checkpoint selection the same as early stopping?
No. The loop always executes ten epochs. It saves the best validation-loss checkpoint and reloads it after training.
42. Why not choose the epoch with highest test accuracy?
That would use final assessment data for model selection and make the reported test score optimistic. Use validation for choices, test for final assessment.
43. Why use train-only normalization?
To prevent held-out data statistics from affecting training. All splits should receive the same training-derived transform.
44. Does seed 42 guarantee identical results on every machine?
No. It controls many randomness sources, but kernels, devices, versions and nondeterministic operations can still produce differences. Saved artifacts and environment metadata improve reproducibility.
45. Which model was better in this experiment?
The LSTM: 88.48% test accuracy versus 85.55%, and macro-F1 0.883496 versus 0.852387. This is a single-seed, fixed-budget comparison, not a universal ranking.
46. Why did the Transformer underperform?
The comparison establishes the outcome, not its cause. Small-data training from scratch, the short budget, model settings, and inductive bias are hypotheses requiring controlled experiments.
47. Which class was most difficult?
Shirt for both models: recall 61.8% for LSTM and 48.9% for Transformer; inspect the true-Shirt row in each confusion matrix.
48. Do fewer parameters guarantee faster inference?
No. FLOPs, sequence length, kernel implementation, parallelism, memory movement and batch size also matter. This Transformer has fewer parameters but higher saved fixed-batch forward time.
49. Can you load the saved checkpoint and resume training exactly?
You can reload weights for inference or begin further training, but the saved payload lacks Adam state and complete mid-run RNG/loader state. It is not an exact resume checkpoint.
50. How would you test whether positional embeddings help?

Patch row floor(13/4)=3; patch column floor(22/4)=5; patch index 7×3+5=26. Local row=1, local column=2, feature index 4×1+2=6. Therefore P[26,6]=Z[0,13,22]. Indices are zero-based.


3. Compute c and h when old c=−0.4, f=0.5, i=0.8, g=0.25, o=0.9.
c = 0.5×(−0.4)+0.8×0.25=0. h=0.9×tanh(0)=0. Forgetting and writing can cancel; a nonzero output gate does not guarantee a nonzero hidden value.


4. Recount the LSTM if hidden size becomes 64.
With input width 28: 4×64×(28+64+2)=24,064 recurrent parameters. Head: 64×10+10=650. Total 24,714. Update the classifier input width as well. This calculation is a proposed variant, not the saved model.


5. What changes if the Transformer uses 8 heads but keeps width 64?
Each head width becomes 8; divisor becomes √8. Q/K/V and output projection parameter counts stay the same for this implementation. Conceptual attention weights have twice as many head matrices. Whether accuracy or runtime improves requires measurement.


6. Why is mean(dim=2) wrong for Transformer pooling here?
At that line tokens are (B,49,64). dim=1 averages patches to (B,64). dim=2 averages features to (B,49), which does not fit Linear(64,10) and loses the intended feature vector.


7. A classifier predicts the correct class with probability 0.25. What is its cross-entropy?
−ln(0.25)=ln(4)≈1.3863. Its prediction can still be correct if all other individual class probabilities are smaller than 0.25. Accuracy and confidence-weighted loss measure different aspects.


8. Explain a counterintuitive LSTM checkpoint choice using the history.
Epoch 8 has higher validation accuracy than epoch 9, but epoch 9 has lower validation cross-entropy. The implementation selects on loss, so epoch 9 is expected. It can reward better-calibrated or less-confidently-wrong scores even when a few more argmax decisions are wrong.

142  def to_representation(image: torch.Tensor, mode: str = "flatten", patch_size: int = 4):
143      """Convert one normalized image to the model's input layout.
144  
145      For row_seq, (1, H, W) becomes (steps=H, features=W), with
146      sequence[t, j] == image[0, t, j]. No pixels are reordered or discarded.
147      col_seq instead walks columns left to right, transposing those axes.
148      patch_seq walks non-overlapping square patches in row-major order,
149      flattening the pixels within each patch in row-major order as well.
150      """
151      if mode == "flatten":
152          return image.reshape(-1)
153      if mode == "image":
154          return image
155      if mode == "row_seq":
156          if image.ndim != 3 or image.shape[0] != 1:
157              raise ValueError("row_seq expects a single-channel image with shape (1, H, W)")
158          return image.squeeze(0)
159      if mode == "col_seq":
160          return image.squeeze(0).t().contiguous()
161      if mode == "patch_seq":
162          if image.ndim != 3 or image.shape[0] != 1:
163              raise ValueError("patch_seq expects a single-channel image with shape (1, H, W)")
164          _, height, width = image.shape
165          if patch_size <= 0 or height % patch_size or width % patch_size:
166              raise ValueError("patch_size must divide both image dimensions")
167          patches = image.unfold(1, patch_size, patch_size).unfold(2, patch_size, patch_size)
168          return patches.contiguous().view(-1, patch_size * patch_size)
169      raise ValueError(f"Unknown representation mode: {mode!r}")

LSTM essentials
  • Input: (B,28,28), 28 row steps.
  • One direction, one layer, H=128.
  • i/f/o are sigmoid; candidate g is tanh.
  • c=f⊙c_old+i⊙g; h=o⊙tanh(c).
  • Zero initial h/c on every forward.
  • h_n: (1,B,128); hidden[-1]: (B,128).
  • Dropout 0.2 → Linear(128,10).
  • 82,186 parameters; selected epoch 9.
  • Test: 88.48%, macro-F1 0.883496.
Transformer essentials
  • Input: (B,49,16), 4×4 patches.
  • Linear(16,64) + learned (1,49,64) positions.
  • 2 pre-norm blocks; 4 heads; d_head=16.
  • Attention softmax(QKᵀ/4)V per head.
  • FFN: 64→128→64, GELU, dropout 0.2.
  • Blocks receive (49,B,64); no mask.
  • Final LayerNorm → mean over patches.
  • Dropout → Linear(64,10).
  • 71,946 parameters; selected epoch 10.
  • Test: 85.55%, macro-F1 0.852387.
