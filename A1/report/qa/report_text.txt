Abstract / Executive Summary
This assignment studies the classification of low-resolution clothing and accessory images using five
neural network configurations: a linear classifier, a multilayer perceptron (MLP), a convolutional neural
network (CNN), a row-sequence long short-term memory network (LSTM), and a patch-based Trans-
former. The central question is how these different input representations and model structures compare
when they share the same data partition, preprocessing, and nominal training budget.
This first report stage establishes the problem and the dataset evidence needed for that comparison.
Fashion-MNIST provides 60,000 official training images and 10,000 official test images, each with 28
by 28 grayscale pixels and one of ten labels. A seed-42 stratified split produces 54,000 training and 6,000
validation images. Every class contributes 5,400 training, 600 validation, and 1,000 test examples. De-
scriptive analysis uses the training subset; validation and test data are used here only for structural checks
and an exact-duplicate audit.
Across all 42,336,000 training pixels, the raw mean is 72.98 and the population standard deviation is
90.06 on the 0–255 scale. Exactly 50.21% of training pixels are zero, while 0 training images are entirely
zero. Class-specific brightness, spatial averages, and variability maps reveal substantial differences in
silhouette and image coverage. Similarity between upper-body garment prototypes motivates later class-
specific error analysis; these descriptive similarities do not determine a trained model’s performance.
The preprocessing pipeline uses a training-only mean of 0.286209 and standard deviation of 0.353160
on the 0–1 scale. The same normalized pixels are exposed as vectors, image grids, row sequences, or
patch sequences without discarding information. CUDA reductions were executed on the local GTX 1660
SUPER and checked against CPU calculations. This document completes Sections 1 and 2. Methodol-
ogy, matched CUDA experiments, model results, and conclusions belong to subsequent stages and are
specified in the accompanying continuation guide.
Keywords: Fashion-MNIST; image classification; exploratory data analysis; training-only normaliza-
tion; CUDA; reproducibility.

Introduction
1.1
Background and Motivation
Image classification maps an image to a semantic category. In an online product catalogue, for example,
an automatic classifier could help organize incoming article images into clothing and accessory cate-
gories. The classification itself is only one part of the system: the reliability of the result also depends
on the dataset, the representation of each image, the separation between training and evaluation data, and
the way model quality and computational cost are measured.
Fashion-MNIST is a useful setting for studying this pipeline. Its compact images allow several neural
network configurations to be investigated on the available desktop GPU. At the same time, the recogni-
tion problem contains visually similar categories and variation within each category. This combination
supports a practical assignment in which the data can be inspected carefully and the experiments can be
reproduced. The dataset was introduced by Xiao, Rasul, and Vollgraf as a benchmark based on fashion
article images[1].
Different neural architectures organize the same input information differently. A linear classifier com-
bines pixel values directly, while an MLP adds learned nonlinear transformations. A CNN processes
neighborhoods on the image grid. An LSTM can read the image as an ordered sequence of rows, and a
Transformer can operate on a sequence of small image patches. Comparing these configurations provides
a way to investigate how spatial structure, sequence ordering, and model capacity interact with a fixed
classification task.
The motivation is therefore both predictive and experimental. A useful study should identify which
implemented configuration performs well, describe the classes it confuses, and explain the resources it
requires. A common data protocol is essential: otherwise differences in splitting, normalization, check-
point selection, or hardware could obscure the comparison.
1.2

1.3
Objectives and Scope
The study has four objectives:
1. Establish a reproducible Fashion-MNIST data protocol, with a fixed stratified split, training-only
normalization, and auditable data provenance.
2. Compare Linear and MLP baselines with the implemented CNN, LSTM, and Transformer, keeping
the dataset and nominal optimization budget consistent.
3. Evaluate predictive quality using accuracy, macro-F1, class-specific measures, and confusion matri-
ces, together with learning curves and image-level error examples.
4. Measure parameter count, training cost, inference latency, and GPU memory on a documented ref-
erence platform, so that quality and efficiency can be interpreted together.
This first stage completes the introduction and dataset analysis. It verifies the local files, the existing
split, class counts, pixel statistics, image variation, exact duplicates, and preprocessing layouts. It does
not introduce new model scores or an architecture ranking. The remaining sections will document the
implementation, verify experimental artifacts, and interpret the results under the agreed protocol.
The dataset is limited to Fashion-MNIST. No additional product photographs, external training data,
pretrained models, or synthetic images are introduced. The shared configuration uses seed 42, ten epochs,
batch size 128, Adam with a learning rate of 0.001, and no data augmentation. These are the existing
assignment settings, not the outcome of a new hyperparameter search.
The local computational reference is the NVIDIA GeForce GTX 1660 SUPER with 6 GiB of GPU mem-
ory, using the existing Windows Python and CUDA PyTorch environment. Existing Linear and MLP
training summaries identify MPS as their original training device; those durations cannot serve as a
matched CUDA training comparison. A subsequent experimental stage must obtain measurements on
this PC under consistent timing scopes and preserve the historical artifacts. Equal epochs also do not
imply equal wall-clock computation or equal parameter capacity. The final discussion must retain these
qualifications.
1.4
Proposed Approach
The approach begins by separating data inspection from model selection. First, verify the local Fashion-
MNIST files and reproduce the cached seed-42 training/validation indices. Next, inspect training images
and compute class balance, brightness distributions, nonzero-pixel coverage, spatial class statistics, and
exact-duplicate checks. Validation and test images do not contribute to the normalization statistics or
training-set visual summaries.
After inspection, scale each raw image to the unit interval and standardize it using one mean and standard
deviation estimated from the 54,000 training images. Change only the layout for the selected model:
a 784-value vector for Linear and MLP, a one-channel spatial grid for CNN, 28 ordered row steps for
LSTM, or 49 ordered 4 by 4 patches for Transformer. Section 2.4 defines these transformations and

2.4
Preprocessing
The EDA shows that the images already share a fixed resolution and class mapping, but differ in bright-
ness, coverage, and spatial appearance. Our preprocessing therefore keeps the original image content and
applies a common numerical transformation before arranging the pixels for each model. The pipeline has
four steps: convert the raw image to a floating-point tensor, scale its intensities, standardize it using train-
ing statistics, and construct the required input layout. The same fitted transformation is used for training,
validation, and test images.

2.4.5
Data Retention and Augmentation Policy
The baseline retains every image and all pixel coordinates. The audit found no entirely blank training
images or exact duplicates across the checked partitions. Brightness and nonzero coverage vary within
each class, but extreme values alone do not establish corruption or an incorrect label. Accordingly, the
EDA does not justify removing dark images, cropping stable background locations, or relabeling visually
ambiguous garments.
No resizing, denoising, binarization, histogram equalization, or dimensionality reduction is applied to the
model inputs. In particular, the nonzero masks, class means, and similarity matrix in the EDA remain
descriptive analyses; they are not extra training features or replacements for the original images. All five
models therefore start from the same grayscale information.
Random augmentation is disabled in the shared baseline configuration. This keeps the initial comparison
independent of architecture-specific augmentation choices. The loader supports optional horizontal flips

2.4.6
Preprocessing Verification
The saved EDA audit checks the transformation against the existing data utility. Over all standardized
training pixels, the measured mean is within 10−6 of zero and the population standard deviation is within
10−6 of one. Independent NumPy calculations reproduce the raw moments and pixel histogram, and the
fitted normalization agrees with the split cache. The same CPU tensor conversion is used by the loader
and the EDA before CUDA calculations, avoiding a change in conversion order between them.
Representation checks compare flattened and row-sequence elements with their source pixels, reconstruct
the image from the patch sequence, and confirm agreement between CPU and CUDA layout conversions.
These checks verify values and ordering, rather than relying only on tensor dimensions. Together with
the fixed split, they establish the input interface for the methodology and implementation sections. They
do not establish classifier accuracy, which requires evaluation of trained models.
2.5
Key Findings and Implications for Methodology
The dataset analysis establishes a controlled starting point for the five-model comparison. Its main find-
ings translate into the following experimental decisions.
1. Class balance supports an unweighted baseline. Each class contributes 5,400 training, 600 vali-
dation, and 1,000 test images. No resampling or class weighting is introduced to address frequency
imbalance. Equal counts do not guarantee equal recognition difficulty, so evaluation must include
per-class precision, recall, and F1 alongside accuracy and macro-F1.
2. Background prevalence must be separated from image validity. Exactly 50.21% of training pixels
are zero, but no training image is entirely blank. Brightness and coverage distributions overlap across
classes. The baseline therefore keeps the grayscale intensities and every image rather than applying
an unsupported brightness threshold or background removal rule.
3. Spatial structure motivates different model representations. Class means retain broad silhouettes,
while variability maps and individual examples show changes that averaging conceals. Vectors pro-
vide the Linear and MLP baselines; the CNN retains the image grid; the LSTM reads ordered rows;
and the Transformer receives ordered patches. All layouts retain the same 784 standardized val-
ues. Architecture comparisons must still account for differences in parameter count and computation
before attributing a performance gap to representation alone.
4. Prototype similarity gives a specific error-analysis question. Coat and Shirt have the highest off-
diagonal prototype cosine similarity, approximately 0.9873. Later confusion matrices should check
whether these and other upper-body categories are frequent directional errors, and example galleries
should examine the corresponding mistakes. Similarity of averages alone does not predict which
model will perform best or establish that any supplied label is incorrect.
5. One fitted preprocessing pipeline supports a consistent comparison. The seed-42 split, cached
