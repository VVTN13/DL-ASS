3
Methodology
This study compares ﬁve supervised classiﬁers for Fashion-MNIST: a linear classiﬁer, a multilayer perceptron
(MLP), a convolutional neural network (CNN), a row-sequence long short-term memory network (LSTM), and
a patch-based Transformer. The comparison examines how diﬀerent representations and learned operations
classify the same image information under a common data and training protocol. These are conﬁgurations of
established model families; the study does not introduce a new architecture. Model capacity varies, so the
experiment compares complete conﬁgurations rather than isolating architecture at a ﬁxed parameter budget.
3.1
Overall System Architecture
The system separates parameter ﬁtting, checkpoint selection, and ﬁnal evaluation into distinct stages. A seed-42
stratiﬁed partition divides the 60,000 oﬃcial training images into 54,000 training and 6,000 validation images.
The oﬃcial 10,000-image test partition retains its supplied examples and labels. Each class contributes 5,400
training, 600 validation, and 1,000 test examples. The partition and preprocessing are shared across all ﬁve
runs; Figure 9 shows their information ﬂow.

3.2
Baseline Approach
The linear classiﬁer provides a reference with no learned hidden representation. It maps the ﬂattened vector
vi ∈R784 directly to ten logits through a fully connected layer with a bias. Its trainable parameter count is
784 × 10 + 10 = 7,850. The model can assign diﬀerent weights to individual pixel positions, but it cannot learn
nonlinear interactions among them. This makes it a useful starting point for assessing the eﬀect of learned
nonlinear features.
The MLP adds two hidden transformations while retaining the same vector input. The ﬁrst layer maps 784
values to 256 features, followed by a rectiﬁed linear unit (ReLU) and dropout with probability 0.2. The second
layer maps 256 features to 128, again followed by ReLU and dropout 0.2. A ﬁnal 128 →10 linear layer produces
logits. Its parameter count is (784 × 256 + 256) + (256 × 128 + 128) + (128 × 10 + 10) = 235,146. The hidden
layers allow nonlinear combinations of pixels, while their dense connectivity imposes no local spatial weight
sharing. Dropout acts during training and is disabled for validation and test inference.
3.3
Proposed Models / Algorithms
The three additional conﬁgurations examine local ﬁltering, sequential aggregation, and attention over image
regions. The term “proposed models” identiﬁes the models selected for this assignment; it does not imply that
CNNs, LSTMs, or Transformers originate in this work. All models are initialized and trained from scratch,
without pretrained feature extractors. Figure 10 summarizes their forward paths.
3.3.1
CNN: Learning Local Spatial Features
The CNN retains the two-dimensional image grid to learn local patterns through shared ﬁlters, following the
convolutional modeling principle of LeCun et al. [1]. Table 7 gives the exact forward path. Both convolutions
use 3 × 3 kernels, stride 1, padding 1, and a bias; ReLU follows each convolution. Both max-pooling layers use
2 × 2 windows with stride 2. The resulting 64 × 7 × 7 tensor is ﬂattened and mapped to 128 features before the
output head.

3.3.2
LSTM: Reading an Image as an Ordered Row Sequence
The LSTM processes each image as 28 spatial steps, using one complete row per step. Removing the single
channel axis gives Si ∈R28×28, where Si,t,j = Zi,0,t,j for zero-based row and column indices t, j ∈{0, . . . , 27}.
Rows are read from top to bottom, and their features remain in left-to-right order. The sequence describes a
static image rather than observations over time. No transpose, padding, or truncated sequence is introduced.
A single unidirectional nn.LSTM layer uses input size 28, hidden size 128, and batch_first=True. The hidden
and cell states are initialized to zero independently on each forward call; no state is carried between images
or batches. Processing all rows yields outputs of shape (B, 28, 128) and ﬁnal hidden and cell tensors of shape
(1, B, 128). Only the ﬁnal hidden state is passed through dropout 0.2 and a 128 →10 linear classiﬁer. There
is no inter-layer recurrent dropout because the network contains one recurrent layer. The LSTM has 82,186
parameters: 4(128)(28 + 128 + 2) = 80,896 in the recurrent module, including PyTorch’s two bias vectors, and
1,290 in the classiﬁer.
The recurrent state summarizes the rows encountered so far, providing a mechanism for combining information
across vertical positions. LSTM gating follows an established recurrent design [2]; the equations below use the
forget-gate form implemented by PyTorch [3]. Using the ﬁnal hidden state creates a compact readout, but its
sequential computation and sensitivity to row order are relevant trade-oﬀs.
3.3.3
Transformer: Attention Across Ordered Image Patches
The Transformer represents each image as a 7 × 7 grid of nonoverlapping 4 × 4 patches, producing 49 vectors
of length 16.
Both patches and their internal pixels follow row-major order, as deﬁned in Section 2.4.
A
learned linear projection maps each patch from 16 to 64 features. A trainable position embedding of shape
(1, 49, 64) is added before dropout 0.2, allowing tokens with similar content at diﬀerent image locations to
remain distinguishable.
Two independently initialized encoder blocks preserve the token dimension (B, 49, 64). Each block uses four
attention heads with 16 features per head, a 64 →128 →64 feed-forward network with GELU activation,
dropout 0.2, and pre-normalization residual connections. Internally the code transposes tokens to (49, B, 64)
for the encoder layers and transposes them back afterward. All patches are present, so neither a padding mask
nor a causal mask is supplied. A ﬁnal layer normalization acts on each token before mean pooling over the 49
positions, dropout 0.2, and a 64 →10 classiﬁer.
This conﬁguration uses patch-based visual input [4] and self-attention [5], with no class token or pretrained
weights. Its 71,946 parameters comprise 1,088 in the patch projection, 3,136 in learned positions, 33,472 in each
encoder block, 128 in the ﬁnal layer normalization, and 650 in the output head. Attention permits interaction
between every pair of image regions within a block; this does not by itself establish an advantage under a short
training budget.

3.6
Evaluation Metrics
Evaluation reloads the validation-selected checkpoint, veriﬁes its source and split ﬁngerprints and normalization
constants against the data loader, and computes predictions without parameter updates. The oﬃcial test set is
used for reporting generalization under the stated protocol. No test score is used by the implemented checkpoint-
selection rule. Prediction records retain each example’s test index, true label, predicted label, conﬁdence, and
correctness, allowing aggregate metrics to be checked against individual outcomes.

3.6.2
Model Size and Timing Boundaries
Model size is measured by the number of trainable scalar parameters, including biases, learned positions, and
layer-normalization parameters. Counts are recomputed from instantiated models and checked against saved
summaries. Parameter count describes storage and capacity, but does not determine runtime because architec-
tures perform diﬀerent operations.
Forward timing uses a ﬁxed device-resident batch of 128 images in inference mode. Ten forward calls warm up
execution; the next 100 calls are timed with device synchronization before and after the interval. If their total
duration is T100 seconds, the reported batch time is 1000T100/100 milliseconds and amortized time per image is
that value divided by 128. This excludes loading and host-to-device transfers and measures batched forward cost
rather than single-request response time. A separate complete test-pass timer includes data loading, transfers,
forward computation, loss, predictions, and conﬁdence extraction; it excludes plotting and artifact writing after
the pass. The current evaluator reports one aggregate timing interval, not a distribution of independent timing
repetitions.
The training timer covers the ten-epoch training/validation loop, epoch logging, and saves of improved check-
points, with device synchronization at its boundaries. It excludes initial data preparation, model/optimizer
construction, and post-loop re-evaluation and artifact generation. Historical MPS and CUDA training dura-
tions must be labeled by device and must not form a matched cross-model speed ranking. Peak allocated or
reserved GPU memory is not measured by the existing trainer/evaluator, so no peak-memory result is asserted
here. Such a comparison requires explicitly instrumented runs under the same device and measurement scope.
