Abstract
This report compares ﬁve neural network conﬁgurations for Fashion-MNIST image classiﬁcation: a Linear
classiﬁer, a multilayer perceptron (MLP), a convolutional neural network (CNN), a row-sequence LSTM and a
patch-based Transformer. The models receive the same pixels, arranged as vectors, image grids, rows or patches.
The study examines how these choices relate to predictive quality, training behavior and computational cost.
The oﬃcial training data is divided into 54,000 training and 6,000 validation images using a stratiﬁed split with
seed 42. The oﬃcial test set contains 10,000 images. Normalization uses statistics from the training partition
only. All ﬁve models use Adam with a learning rate of 0.001, batches of 128 and ten epochs, without data
augmentation. The checkpoint with the lowest validation loss is evaluated on the test set.
The CNN achieves the highest test accuracy, 91.94%, and macro-F1, 0.9189. MLP and LSTM obtain 88.50%
and 88.48% accuracy, followed by Transformer at 85.55% and Linear at 84.26%. The CNN makes 806 errors,
compared with 1,150 for the MLP. It also has the most parameters, at 421,642. Under the recorded GTX 1660
SUPER inference measurement, the MLP takes 0.247 milliseconds per 128-image forward batch and the CNN
takes 1.074 milliseconds.
Class-level analysis shows that upper-body garments remain the main diﬃculty. The CNN correctly identiﬁes
71.8% of Shirt images, compared with 98.8% of Trouser images. Its mistakes often occur between Shirt, T-
shirt/top, Pullover and Coat. These errors are consistent with the similar silhouettes observed in the training
data, although that observation alone does not establish why an individual prediction failed.
The results favor the implemented CNN for accuracy and show the MLP as a useful lower-cost alternative in
the recorded batch timing. Conclusions are limited to one seed and the tested conﬁgurations. Model capacity
diﬀers, training hardware is not shared across all ﬁve runs, and the study does not estimate variation across
repeated training runs.
Keywords: Fashion-MNIST; image classiﬁcation; CNN; LSTM; Transformer; model comparison.

Introduction
1.1
Background and motivation
Image classiﬁcation assigns a category to an image. For a product catalogue, this could help organize new items
into clothing and accessory groups. Reliable classiﬁcation depends on more than the model: the data split,
preprocessing and evaluation procedure also aﬀect how a result should be interpreted.
Fashion-MNIST provides a manageable setting for studying this process [1]. Its small grayscale images make it
practical to train several models, while visually similar categories create a useful recognition challenge. A shirt
and a pullover, for example, may have similar outlines even though they belong to diﬀerent labels.
Diﬀerent architectures use image information in diﬀerent ways. A Linear classiﬁer combines pixel values directly.
An MLP learns nonlinear combinations of pixels. A CNN learns local spatial patterns, an LSTM reads an ordered
sequence of rows, and a Transformer combines information across image patches. Comparing these approaches
helps explain what each design contributes in a small, controlled experiment.
1.2
Problem statement
The task is supervised, single-label classiﬁcation into ten categories. A raw image is X ∈{0, . . . , 255}28×28 and
its label is y ∈{0, . . . , 9}. After preprocessing T, a model with parameters θ produces ten scores:
fθ(T(X)) = z ∈R10,
ˆy = arg
max
k∈{0,...,9} zk.
The prediction describes the complete image. The study does not locate objects within an image or assign
several labels to one image.
The main question is how the ﬁve implemented conﬁgurations compare when they use the same training exam-
ples, normalization and epoch budget. We examine both overall performance and the types of mistakes hidden
by an aggregate score.
1.3
Objectives and scope
The project has four objectives:
1. Inspect the dataset and establish a reproducible preprocessing and split protocol.
2. Implement and compare Linear, MLP, CNN, LSTM and Transformer classiﬁers.
3. Evaluate accuracy, macro-F1, learning behavior and class-speciﬁc errors.
4. Relate predictive quality to parameter count and documented runtime measurements.
The experiments use Fashion-MNIST only, with no pretrained weights, external training data or augmenta-
tion. Each model is trained once using seed 42 and ten epochs. The comparison concerns these particular
conﬁgurations; architecture, parameter count and computation are not independently controlled.
1.4
Report approach

common training procedure.

Methodology
The experiment compares ﬁve ways of classifying a clothing image: Linear, MLP, CNN, LSTM and Transformer.
Each model receives the same image information, but processes it diﬀerently. Linear and MLP use a pixel vector,
CNN uses the image grid, LSTM reads image rows, and Transformer works with small image patches. This
section describes the implemented models and the procedure used to train and evaluate them.
3.1
Shared data and workﬂow
Fashion-MNIST contains ten classes of 28 × 28 grayscale images [1]. As described in Section 2, the oﬃcial
training set is divided into 54,000 training images and 6,000 validation images using a stratiﬁed split with
seed 42. The oﬃcial test set contains 10,000 images. Training ﬁts the model weights, validation chooses which
saved weights to keep, and testing measures the selected model.
All models use the preprocessing from Section 2. Pixel values are divided by 255 and standardized with the
training mean and standard deviation, approximately 0.286209 and 0.353160. The same constants are reused
for validation and testing. No images are resized, augmented or removed.

3.2
Pixel-based baselines
3.2.1
Linear classiﬁer
The Linear model assigns a weight to each pixel for each class. For a ﬂattened image x ∈R784, its output is
z = Wx + b,
W ∈R10×784,
b ∈R10.
The largest score determines the prediction. This model provides a small baseline with no hidden layer. It can
learn which pixel positions support a class, but cannot learn nonlinear combinations of those pixels.
3.2.2
Multilayer perceptron
The MLP adds two hidden layers with 256 and 128 units. Each hidden layer is followed by ReLU and dropout
with probability 0.2. ReLU sets negative values to zero, while dropout randomly suppresses some activations
during training.
784 −→256 −→128 −→10.
The hidden layers allow the MLP to learn nonlinear relationships among pixels. The image is still treated as
a vector: nearby pixels do not receive a special shared operation. Dropout is disabled during validation and
testing.

3.3
Models for spatial and sequential structure
3.3.1
Convolutional neural network
The CNN keeps the two-dimensional image layout. Convolution applies the same small ﬁlter at diﬀerent image
positions, allowing the network to learn local patterns such as edges and contours [3]. Our model has two
convolutional blocks, followed by a dense classiﬁer.
Both convolutions use 3 × 3 kernels, stride 1 and padding 1, so they preserve height and width. ReLU follows
each convolution. A 2×2 max-pooling layer then keeps the largest value in each window and halves both spatial
dimensions. The ﬁrst block produces 32 feature maps and the second produces 64.

3.3.2
Row-sequence LSTM
An LSTM maintains a hidden state and a memory state while reading a sequence [4]. Here, the sequence comes
from a static image. The ﬁrst step receives the top row, the second receives the next row, and the last receives
the bottom row. Each step contains 28 pixel values.
For a standardized image X, row t is rt = X0,t,:. The batch shape (B, 28, 28) means batch, row steps, pixel
features. The two dimensions of size 28 have diﬀerent roles; the sequence is not a sequence of diﬀerent images.
Row 1 −→Row 2 −→· · · −→
Row 28
One shared LSTM reads the rows in order.
h28 ∈R128 −→dropout 0.2 −→dense layer −→10 scores
The implementation uses one forward LSTM layer with 128 hidden units. Its hidden and memory states start
at zero for each image. The gates control what information is retained and updated as successive rows are read.
After the 28th row, the ﬁnal hidden state is passed through dropout and a linear classiﬁer. No state is carried
from one image to another.
This design tests whether a compact summary built from ordered rows is useful for classiﬁcation. It introduces
a top-to-bottom reading order, whereas the CNN processes local neighborhoods throughout the image.

3.4
Patch-based Transformer
The Transformer uses attention to combine information from diﬀerent parts of an image [5]. The input follows
the image-patch idea [6], using a small conﬁguration suited to the 28 × 28 images.
3.4.1
Patch tokens and position information
Each image is divided into a 7 × 7 grid of non-overlapping 4 × 4 patches. Each patch is ﬂattened into 16 values.
Patches are ordered from left to right across each row of the grid, then from top to bottom. A learned linear
layer maps each patch from 16 values to 64 features. A learned positional vector is added so the model can
distinguish patch locations:
ej = Wpj + b + qj,
j = 1, . . . , 49,
where pj ∈R16 is a patch, W ∈R64×16 is the projection, and qj ∈R64 is its position vector. Dropout with
probability 0.2 is applied after this addition.
3.4.2
Attention blocks and classiﬁcation
Two encoder blocks process the 49 tokens. Each block uses four attention heads, a feature width of 64, and a

Evaluation mode disables

Epoch loss is weighted by the number of images in each batch, so a smaller ﬁnal batch does not receive the

Training metrics are collected while the weights change; validation metrics use the ﬁxed weights at the end of

Runtime, reproducibility and comparison scope
3.8.1
Runtime measurements
Training time covers the ten-epoch training and validation loop, including saving improved checkpoints. It
excludes data preparation before the loop and the ﬁnal checkpoint reload and validation after it.
Forward-pass timing uses a ﬁxed batch of 128 images already on the device. After ten warm-up calls, the
program times 100 forward calls and averages their duration. Dividing the batch time by 128 gives time per
image at that batch size. Device synchronization is performed around the timed region. This measurement
excludes data loading and host-to-device transfers and describes batched throughput, not the latency of a
single-image request.
A separate timer measures the complete test pass, including loading, transfers, model execution, loss and
prediction collection.
It excludes later metric summaries and plots.
The two measurements are reported
separately because they cover diﬀerent work.
3.8.2
Reproducibility
The implementation separates data preparation in a1/data.py, model deﬁnitions in a1/models.py, training
in a1/train.py, and testing in a1/evaluate.py. Conﬁguration ﬁles specify the shared training settings. The
split cache records the training and validation indices and the normalization constants.
Each run saves the selected checkpoint, epoch history and a summary of its conﬁguration and environment.
Evaluation checks the recorded data and split hashes and normalization values before using the checkpoint. It
also saves per-image predictions so that the reported scores can be checked again.

Discussion and Limitations
6.1
What the comparison shows
The strongest result comes from the CNN. Its local ﬁlters and pooling provide a natural way to process the
spatial structure of clothing images. The class-level results show gains across all categories, including the similar
upper-body garments that trouble the baselines. This is consistent with the usefulness of local spatial features
in this task.
That explanation remains an interpretation. The CNN also has the largest parameter count, and no ablation
isolates the contribution of convolution, pooling, width or regularization. The experiment demonstrates a better
result for this conﬁguration, rather than proving a single cause for the improvement.
The MLP is a useful practical baseline. It improves substantially over Linear and nearly matches the LSTM
while requiring less recorded forward time. The LSTM achieves similar overall accuracy with fewer parameters,
but reading the image sequentially does not provide an accuracy advantage in this run. Its ﬁnal hidden state
must summarize the rows before classiﬁcation.
The Transformer has the fewest parameters among the four nonlinear models, but it has the longest recorded
forward time and a lower test score than MLP, CNN or LSTM. Attention is not automatically an improvement
under a small, ﬁxed training conﬁguration. Since its validation loss is still decreasing at epoch 10, longer training
is a plausible follow-up, not an established remedy.
6.2
Limits of the evidence
1. One seed per model. The report does not estimate variation from initialization or data ordering. Small
score diﬀerences, especially between MLP and LSTM, should not be treated as stable.
2. Unequal capacity and computation. The models share an epoch budget but have diﬀerent parame-
ter counts, operations and training durations. The study is not a capacity-matched or compute-matched
ablation.
3. Restricted optimization. There is no systematic learning-rate, width, dropout or schedule search. A
shared setting may suit some models better than others, and ten epochs need not be suﬃcient for every
conﬁguration.
4. Hardware and timing scope. All cost measurements use CUDA on the GTX 1660 SUPER. Baseline
costs come from separate repetitions; classiﬁcation scores retain the original checkpoints. Inference uses only
one batch size and a short benchmark, without repeated-session timing variation. Peak model memory is
not recorded.
5. Limited image domain.
Fashion-MNIST contains small grayscale images.
The experiment does not
measure robustness to color, backgrounds, occlusion, new product styles or distribution shift.
6. Post-evaluation analysis.
Confusions and example images explain the existing results.
They do not
justify tuning against the test set and reporting the same set as an untouched ﬁnal evaluation.
6.3
Next experiments
The ﬁrst priority is to repeat each conﬁguration across several seeds and report the mean and variation of
accuracy and macro-F1. Training-speed comparisons should repeat all ﬁve models in controlled sessions on the
same hardware and timing scope to quantify runtime variation.
Next, use validation data to compare longer schedules and modest learning-rate changes, especially for Trans-
former. Separate ablations can examine CNN width, LSTM readout and patch size while controlling one factor
at a time. Augmentation and calibration are further candidates. Any new settings should be selected through
validation before a clearly documented ﬁnal evaluation.

Conclusion
This project compares ﬁve neural network conﬁgurations through a common Fashion-MNIST pipeline. The data
is split into ﬁxed training, validation and test partitions, normalized using training statistics, and presented as
vectors, image grids, row sequences or patch sequences. All models use the same ten-epoch training budget and
validation-loss checkpoint rule.
The CNN gives the strongest recorded result: 91.94% test accuracy and 0.9189 macro-F1. It makes 806 errors
on 10,000 images, 344 fewer than the MLP. Its improvement appears across all ten class F1 scores, although
Shirt remains diﬃcult, with 71.8% recall. Most remaining CNN errors occur among T-shirt/top, Pullover, Coat
and Shirt.
MLP and LSTM obtain nearly equal accuracy at 88.50% and 88.48%. Their two-image diﬀerence is too small
to support a general ranking, and their individual predictions diﬀer substantially. Transformer reaches 85.55%,
above the Linear baseline at 84.26%, but below the other nonlinear models under this conﬁguration and training
budget.
For this assignment, CNN is the preferred conﬁguration when test accuracy is the main criterion. MLP is a
useful alternative when the recorded forward cost matters: it trades some accuracy for a substantially shorter
batch forward time. LSTM is smaller than MLP in parameter count, but that smaller count does not translate
into faster measured inference.
The broader lesson is that a more elaborate architecture does not guarantee a better result under a ﬁxed exper-
imental budget. Input structure, capacity, optimization and runtime must be considered together. Repeated
seeds and controlled follow-up experiments are needed before these single-run ﬁndings can be extended into
stronger claims.

C.2
Commands to reproduce the experiment
Create a Python 3.12 environment and install requirements-windows.txt on the CUDA reference platform. For example,
run the following from A1 in PowerShell:
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
$env:CUBLAS_WORKSPACE_CONFIG = ’:4096:8’
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m a1.train --model cnn --config configs/cnn.json
.\.venv\Scripts\python.exe -m a1.evaluate --checkpoint runs/m2/cnn/best.pt
.\.venv\Scripts\python.exe tests/verify_run.py --model cnn
Linear and MLP use configs/m1.json; LSTM and Transformer use configs/lstm.json and configs/transformer.json.
Change the model name and checkpoint directory accordingly. To reproduce the baseline CUDA cost repetitions without
replacing the original run ﬁles, execute the following from A1:
.\.venv\Scripts\python.exe -m a1.cuda_baselines
This uses configs/m1_cuda.json, which explicitly requires CUDA and writes to runs/cuda_baselines. It trains both
baselines, evaluates their selected checkpoints on CUDA and veriﬁes all saved test predictions.

Checks performed for this report
Report checks recompute metrics and confusion counts for all 50,000 original test predictions and verify checkpoint
selection, normalization, data hashes and ﬁle digests.
Both new CUDA baseline checkpoints pass validation/test metric recomputation, veriﬁcation of all 20,000 saved predic-
tions and CPU/CUDA agreement on 128 images per model. Records accompany the checkpoints. Losses and timings
use saved summaries; report evidence and document checks are in qa.
